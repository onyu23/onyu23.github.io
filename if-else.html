C 语言的 if-else 与声明位置

2026-10-18 · 标签：C语言 · 踩坑记录

学 C 语言的第一周，我踩了四个坑。每个坑都值得记下来，因为它们都属于同一类： 语法完全合法，编译器却不吭声，程序悄悄出错。

坑一：变量声明必须写在语句之前

我写的第一段代码是这样的：

int main(void)
{
    int money = 286;
    int n50 = money / 50;
    money %= 50;
    int n20 = money / 20;   /* 语句之后声明 */
    return 0;
}

VC6 直接报错：

error C2143: syntax error : missing ';' before 'type'

原因：VC6 遵循的是 C89 标准，它要求所有变量声明必须集中在块的开头， 出现在任何语句之前。而 C99 及以后的标准放宽了这条限制。

用 GCC 的 -std=c89 -pedantic 编译同一段代码，它给的是：

warning: ISO C90 forbids mixed declarations and code

同一个错误，VC6 报 error（直接失败），GCC 只报 warning （照常生成程序）。所以「能编译通过」不代表代码规范。

改法

int main(void)
{
    int money = 286;
    int n50, n20;          /* 声明全部集中到开头 */

    n50 = money / 50;
    money %= 50;

    n20 = money / 20;
    money %= 20;

    return 0;
}

坑二：全角字符

有一行代码怎么看都对，编译却报错：

money %= 20；    /* 注意行尾 */

报错是这样的：

error C2018: unknown character '0xa3'
error C2018: unknown character '0xbb'

问题在于行尾是个全角分号 ；，而不是半角 ;。 它的 UTF-8 编码是 EF BC 9B，GBK 编码是 A3 BB，所以编译器报的是字节值。

肉眼几乎分辨不出来，但代码就是错的。这类字符还有：

字符全角半角全角 UTF-8 字节
分号；;EF BC 9B
括号（）()EF BC 88 / EF BC 89
逗号，,EF BC 8C
引号“ ”"E2 80 9C / E2 80 9D

根因：敲代码时输入法还在中文状态。养成习惯——写代码前先切到英文半角。

坑三：= 和 ==

想判断一个数是偶数，我写成了：

int a = 5;
if (a % 2 = 0)          /* 应该是 == */
{
    printf("even\n");
}

报错：

error C2106: '=' : left operand must be l-value

翻译过来是「赋值号左边必须是左值」。a % 2 算出来是个临时值， 没有内存地址可以写入，所以不能放在赋值号左边。

这个错误反而救了我

如果写成 if (a = 0)——左边是变量 a，是合法左值—— 编译器一个字都不报，因为语法完全正确。但它实际做的是「把 0 赋给 a」， 然后判断这个赋值表达式的值（0，即假），后续逻辑全错。

写法左边是什么编译器反应
if (a = 0)变量（lvalue）不报错，最高警告级别才提示
if (a % 2 = 0)临时值（rvalue）报错 C2106

所以写 if (条件) 时，多用 ==，别手滑写成 =。

坑四：指针漏掉星号

写一个「返回数组最大最小值」的函数时需要用到指针参数。正确写法：

void findMinMax(const int *a, int n, int *minimum, int *maximum)
{
    int i;
    *minimum = a[0];         /* 注意这个星号 */
    *maximum = a[0];

    for (i = 1; i < n; i++)
    {
        if (a[i] < *minimum) *minimum = a[i];
        if (a[i] > *maximum) *maximum = a[i];
    }
}

我漏掉星号，写成了 minimum = a[0];，两个编译器的反应完全不同：

编译器反应
GCC 14+error：assignment to 'int *' from 'int' makes pointer from integer
VC6warning C4047，照样生成 exe

我用 VC6 编出来的那个 exe 跑了一下，结果是：

退出码 -1073741819  (0xC0000005 ACCESS_VIOLATION)

程序崩溃了。因为 minimum = a[0] 把指针的地址改成了数值 3， 下次 *minimum 就去访问地址 3，直接违反内存访问规则。

教训：VC6 的 warning 不能当成「没问题」。看到 C4047 这类 「指针层级不匹配」的警告，一定要查，否则就是运行时崩溃。

四个坑的汇总

坑报错为什么
声明写在语句后 C2143 C89 要求声明集中在块首；C99 才放宽
全角分号 C2018 非 ASCII 字符，报的是字节值
= 当成 == C2106 临时值不是左值，不能赋值
指针漏 * C4047 把整数当成了指针，运行时崩溃

一句话总结

C 语言编译器只检查语法和类型， 不检查意图。凡是「语法正确但语义错误」的代码，它都不会拦你。 所以写完程序一定要自己跑几组数据，特别是边界值。

成绩分档统计：计数器、循环与平均值的七个坑

2026-10-22 · 标签：C语言 · 循环 · 分类统计

这次的题目是「按分数分档统计人数」：给 n 个 0~100 的整数成绩，按 A（90~100）、B（80~89）、C（70~79）、D（60~69）、F（0~59）五档， 输出各档人数，空格隔开。

题目本身一分钟就能读懂，我却写了很多版才对。回头看，每一版都栽在不同的小地方， 而它们恰好覆盖了「循环 + 计数」这类题的全部基础坑。这篇把它们一次说清楚。

题目骨架：一个计数器 + 从高到低判断

这类题的核心只有两句话：读一个数，判断它落在哪一档，把那一档的计数器加一。 不需要数组，也不需要把成绩存下来。

成绩档位判断写法
90 ~ 100As >= 90
80 ~ 89Bs >= 80
70 ~ 79Cs >= 70
60 ~ 69Ds >= 60
0 ~ 59Felse

关键是：只写每档的下界，从高到低判断。因为 else if 从上往下走， 第一个成立就跳出去，所以 90 分的 >= 80 根本轮不到判断， 不会出现「一个人被统计两次」的问题。

#include <stdio.h>

int main(void)
{
    int a = 0, b = 0, c = 0, d = 0, f = 0;   /* 五个计数器 */
    int n, s, i;

    scanf("%d", &n);
    for (i = 0; i < n; i++) {
        scanf("%d", &s);
        if (s >= 90)      a++;     /* 从高到低 */
        else if (s >= 80) b++;
        else if (s >= 70) c++;
        else if (s >= 60) d++;
        else              f++;
    }

    printf("%d %d %d %d %d\n", a, b, c, d, f);
    return 0;
}

就这三十行，但我第一版写出来是这样（只摘循环部分）：

while (n--)
    scanf("%d", s);
    if (s >= 90) a++;

编译居然「通过」了（只有警告），运行直接崩溃。下面把七个坑一个个拆开。

坑一：scanf 少了 &

上面那行 scanf("%d", s) 少了取地址符。GCC 的警告是：

warning: format '%d' expects argument of type 'int *', but argument 2 has type 'int'

翻过来就是：scanf 要的是「int 的地址」，你给的是「int 的值」。 s 这时候还是随机值，相当于让 scanf 往一个随机地址写数据。

实测运行这条程序，退出码是 3221225477，也就是 0xC0000005 （ACCESS_VIOLATION，访问冲突）——一段输出都没有。

函数参数写法原因
scanf("%d", &n)要 &要把值写进变量，必须知道它住哪
printf("%d", n)不要 &只是读这个值去打印

坑二：while 后面漏了大括号

while (n--)
    scanf("%d", &s);        /* 只有这一句属于 while */
if (s >= 90) a++;          /* 这几句在循环外面 */
else if (s >= 80) b++;

没有 { } 时，while 只包含紧随其后的一条语句。 于是实际执行的是：把 5 个数全部读进 s，循环结束后只对最后那个数（52）做一次判断。

结果：5 个人的成绩，只统计了 1 个人，输出 0 0 1 0。

GCC 对这种「缩进看起来像一组、实际只包一句」的代码有专门的警告：

warning: this 'while' clause does not guard... [-Wmisleading-indentation]

看到 misleading-indentation（误导性缩进）就该立刻怀疑是不是漏了大括号。

坑三：判断顺序从低到高写

第二个版本我把条件顺序写成了这样：

if (s >= 50)      a++;
else if (s >= 70) b++;
else if (s >= 90) c++;
else              d++;

看起来「50、70、90 都写了」，实际上 >= 50 一成立就跳走了， 50 以上的分数全部进了第一档，后两个分支永远执行不到。

用 5 个成绩（45、62、78、90、52）实测，输出是 4 0 0 1 -1218343303： 4 个大于等于 50 的全算给了第一档，只有 45 落到最后一档，最后一个数是没初始化导致的随机值（见坑四）。

规则：区间判断一律从高到低写，每个分支只写自己的下界。 这样 90、80、70、60 这些边界值会自然归入更高的那一档，不需要写 s >= 80 && s <= 89。

坑四：sum 没初始化

加平均值之后，我声明了 int n, s, sum; 就直接 sum += s;。 局部变量不初始化，初值是内存里的随机垃圾，于是总和是从一个随机数开始累加的。

warning: 'sum' may be used uninitialized [-Wmaybe-uninitialized]

实测输出里的平均值是 -1218343303。计数器 a/b/c/d 都必须 = 0， 累加器 sum 也一样。

坑五：while (n--) 之后，n 已经不是原来的 n 了

为了求平均，我最后写了 sum / n，结果输出 1 2 1 1 -327—— 人数全对，平均值却是个负数。

原因是 while (n--) 的循环要等 n 减到 0、判断为假才退出， 退出时 n 已经变成 -1。327 / (-1) = -327。

两种改法：

改法一：先把人数存一份

int n, w, sum = 0, total;

scanf("%d", &n);
total = n;                 /* 存下来 */
while (n--) {
    ...
}
printf("%d %d %d %d %d\n", s, m, o, f, sum / total);

改法二：用一个计数变量，别动 n（推荐）

int n, w, sum = 0, i = 0;

scanf("%d", &n);
while (i < n) {
    scanf("%d", &w);
    sum += w;
    ...
    i++;
}
printf("%d %d %d %d %d\n", s, m, o, f, sum / n);   /* n 还是原值 */

这就等价于 for (i = 0; i < n; i++)。循环变量只用来数次数， 原始数据（这里是 n）要留给后面用——这是循环里最容易忽略的一条。

坑六：输出顺序和变量含义对不上

我用 a、b、c、d 当计数器，按「从高到低」的顺序赋值：

变量实际含义
a90 分及以上（A）
b80~89（B）
c70~79（C）
d60~69（D）

但题目要求按 A B C D F 输出，我却写成了 printf("%d %d %d %d %d", a, b, c, d, f)—— 在另一版（档位是 F O N S）里，样例就输出成了 1 1 2 1 65， 而正确答案是 1 2 1 1 65：数字没算错，顺序错了。

这个问题光看代码很难发现，因为每个数字都是对的。最好的预防方式是 变量名直接叫 s/m/o/f 或 a/b/c/d/f， 让名字本身就说明它是哪一档。

坑七：漏一个分号，报出一串错

        i++        /* 少了分号 */
    }
    printf(...);

编译输出是这样的（节选）：

error: expected ';' before '}' token
error: 'else' without a previous 'if'

只有第一条是真错。缺了分号后，编译器把 i++ 和后面的 } 连在一起解析，语法树彻底乱了，于是「找不到 if 的 else」这种 莫名其妙的错误就跟着冒出来。

经验：一堆报错先看第一条，修完重新编译，往往后面的都消失了。

编译器是第一道防线：用 -Wall

上面七个坑里，有四个是编译器已经提醒过我的，只是我没认真看： 缺 & 有 -Wformat， sum 没初始化有 -Wmaybe-uninitialized， 漏大括号有 -Wmisleading-indentation。加上 -Wall 编译：

gcc -O2 -Wall -Wextra -o main main.c

提醒不等于错误，程序照样能编出来，所以最容易被忽略。 但它们几乎都指向「运行时会出错」，看到就该停下来查。

整数除法与数据范围

平均值用的是整数除法：

sum / n     /* 两个 int 相除，C 自动向下取整 */

327 / 5 = 65，小数部分直接舍去，正好符合题目「向下取整」的要求， 不需要 <math.h> 的 floor，也不用转 double。

顺便算一下会不会溢出：n ≤ 1000，成绩最大 100，总和最多 100000； int 能存到约 21 亿，绰绰有余。判断溢出的办法是 把最大值代进去算一遍，而不是凭感觉用 long long。

完整代码（含平均值）

这是后来做的那道「体检体重分档」练习（S：小于 50，N：50~69，O：70~89，F：90 及以上， 另输出平均体重）的最终版本，一次 AC：

#include <stdio.h>

int main(void)
{
    int s = 0, m = 0, o = 0, f = 0;   /* 四档人数，名字即档位 */
    int n, w, sum = 0, i = 0;

    scanf("%d", &n);
    while (i < n) {
        scanf("%d", &w);
        sum += w;
        if (w >= 90)      f++;
        else if (w >= 70) o++;
        else if (w >= 50) m++;
        else              s++;
        i++;
    }

    printf("%d %d %d %d %d\n", s, m, o, f, sum / n);
    return 0;
}

样例 5 / 45 62 78 90 52 输出 1 2 1 1 65， 在本地 OJ 上 10 个测试点全过，100 分。

知识点小结

  • 分类统计的骨架：一个计数器数组或几个计数变量 + 从高到低的 if-else + 每个数加一次。
  • else if 的短路特性：第一个成立的判断会吃掉后面所有判断，所以顺序决定结果。
  • 局部变量必须初始化，计数器与累加器尤其如此。
  • 循环变量与数据变量要分开，别把后面还要用的 n 减没。
  • scanf 要地址、printf 要值，这一对最常错。
  • 花括号不是装饰，它决定哪些语句属于循环。
  • 整数除法天然向下取整，但要注意除数和数据范围。
  • 先修第一条错误、再重新编译，别被连锁报错吓到。
  • -Wall -Wextra 是最便宜的自查方式。
  • 样例 + 边界值自测，交题前跑一遍。

这类题不难，难的是「每一处都差一点点」：少一个 &、少一对花括号、 条件顺序颠倒、n 被减坏、输出顺序反了……它们单独出现时都只错一点点， 叠加起来就变成「怎么改都不对」。把每种症状和原因对应起来记，比背代码有用得多。
